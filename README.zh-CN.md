# 当你的 agent 对你撒谎

**一份验收踩坑账本：4 台机器、3 个 runtime 的编码流水线**（其中一个节点已下线）

> 英文正文 → [when-your-agents-lie-to-you.md](when-your-agents-lie-to-you.md) · **23 条** · 约 8,000 词

## 这是什么

不是框架，不是 benchmark。是一个团队几个月真实跑出来的**失败模式清单**——每一条都是"绿了但其实没做"，或"红了但其实做完了"。
格式统一：**症状 → 代价 → 能抓住它的那个测试 → 修法**。

适用前提：agent 不在一台机器上，**写代码的和验收的不是同一台**。
如果你的场景是单机 + 一个 CLI + PR 流程，这套东西对你没用，去看 4x 或 Liza。

## 三条最反直觉的

**1. 退出码不告诉你活干没干。**
三种实测：进程失败但活干完了（`rc=1`、四个目标文件已改、门禁 10/10 全绿）；进程成功但什么都没执行（`rc=0`，工具调用被当成文本打印出来）；最荒谬的一种——门禁说 pass、账本说 fail，同一轮、同一个步骤。
规则：**退出码和门禁是两个独立信号，由门禁拍板**。非零退出 + 门禁通过 = 记一条异常，不是判失败。

**2. 你的验证自己也会骗你。**
23 条里 19 条是这个方向——比 agent 撒谎更危险：agent 撒谎至少磁盘还能查，验证撒谎会告诉你"磁盘没问题"。
例：`skip`（未评估）在下游被当成 `pass`；两边 SHA-256 相同、内容断言却失败（一边 UTF-16LE，`grep` 一个 ASCII 词都找不到）；磁盘检查在"两个文件"的 fixture 上毫秒通过，到真实主机上走了 **191,803 个文件**、卡了 **2 小时 44 分**，改后有界扫描 289 ms。

**3. 规则"知道"不等于规则"执行"。**
一组 7 次凭据泄露、7 条不同命令；同一句"绝不打印密钥"写在文档里、写在 prompt 里，一次都没拦住。
另一组：spec / plan / tasks 三份文档各自自洽、彼此漂移；"完成"靠读 diff 和感觉。
一句话：**一条规则失败超过两次，就停止改写它，开始建执行它的面。**

## 最后站住的结构

五层，每层都把一句"声称"变成一次"观测"：
证据门禁 → 三态传播（通过 / 失败 / 未评估）→ 内容指纹存证 → 增量观测 → 显式成本上限。

## 想直接用

看 **§5 迁移清单**：五步，每步都带"前置条件 / 机器可判据 / 可观测失败信号 / 退路"，
外加一个 6 行的 `expect` 骨架，和三个第一天就该内建的旋钮（`RUN_CHECK_TIMEOUT`、`SCOPE_MAX_FILES`、`PIPELINE_SANDBOX_ROOT`）。
